# Записи об архитектурных решениях (ADR)

Здесь фиксируются значимые технические решения — те, которые дорого переигрывать
и о которых через месяц обязательно спросят «а почему так?».

## Что записывать

Записывай, если решение:
- влияет больше чем на один пакет;
- отменяет ранее принятое решение;
- было выбрано из нескольких равнозначных вариантов;
- выглядит странно без объяснения контекста.

**Не записывай** рутину: выбор имени метода, форматирование, локальные детали реализации.

## Формат

Файл `NNNN-краткое-название.md`, нумерация сквозная. Внутри:

```markdown
# NNNN. Название решения

**Статус:** предложено | принято | заменено на NNNN | отклонено
**Дата:** ГГГГ-ММ-ДД

## Контекст
Что за ситуация, какие ограничения, почему вообще пришлось выбирать.

## Варианты
Что рассматривали и чем варианты отличаются. Минимум два.

## Решение
Что выбрали.

## Последствия
Что становится проще, что сложнее, за что придётся заплатить позже.
```

## Правила

- ADR **неизменяем** после принятия. Передумали — заводим новый со статусом
  «заменяет NNNN», старому ставим «заменено на MMMM». Историю решений не переписываем.
- Ссылка на ADR — в описании PR, который это решение реализует.
- Одна страница максимум. Если не помещается — решение сформулировано нечётко.
