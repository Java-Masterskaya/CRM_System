# CRM_System

Многоарендная CRM-система приёма и ведения заявок на обработку данных.
Клиент подаёт заявку — оператор ведёт её по процессу до выполнения. Система следит
за сроками, распределяет нагрузку между операторами и уведомляет участников.

**Стек:** Java 21 · Spring Boot 3 · Gradle · PostgreSQL

## Правила, которые нельзя нарушать

1. **Идентификатор арендатора берётся только из токена.** Никогда из тела, пути или
   параметров запроса. Одна ошибка здесь — утечка данных между компаниями.
2. **Запрет по умолчанию.** Всё, что не разрешено явно, закрыто.
3. **Чужая сущность не существует.** Обращение к недоступному объекту возвращает
   «не найдено», а не «запрещено».
4. **Схема БД — только миграциями.** Автогенерация схемы запрещена.
5. **Одна задача — одна ветка — один PR.** Ветка живёт не дольше двух дней.
6. **Секретов в репозитории нет.** Все чувствительные значения — из окружения.

Полное определение готовности задачи — в [SPEC, раздел 8.2](docs/SPEC.md).


## Запуск и сборка

### Сборка проекта
```bash
./gradlew build
```
Запускает тесты, Checkstyle, SpotBugs и проверку покрытия.

### Проверки кода
```bash
./gradlew check
```
Checkstyle — Google Java Style
SpotBugs — статический анализ
Отчёты в `build/reports/checkstyle` и `build/reports/spotbugs`.

### Запуск тестов
```bash
./gradlew test
```

### CI
`.github/workflows/ci.yaml` — запускается на PR и push в `main`: Checkstyle, SpotBugs, тесты, покрытие.
`.github/workflows/dependency-check.yaml` — OWASP Dependency-Check, по понедельникам в 06:00 UTC и вручную через workflow_dispatch. PR не блокирует.

### Запуск приложения
```bash
./gradlew bootRun
```

## Локальное окружение (Docker Compose)

Проект запускается вместе со всеми необходимыми сервисами (PostgreSQL 16 и почтовая заглушка MailHog) одной командой с помощью Docker Compose.

### Подготовка
Перед первым запуском скопируйте файл с примером переменных окружения:
```bash
cp .env.example .env
```

### Эндпоинты API
Базовый префикс всех эндпоинтов: /api/v1

Служебный эндпоинт проверки работоспособности:
GET http://localhost:8080/api/v1/health

### Уровни тестирования и их запуск

Мы разделяем тесты на быстрые (Unit) и тяжелые (Integration) с помощью стандартных Gradle-плагинов или разделения по имени (Unit тесты заканчиваются на `Test`, интеграционные на `IT`).

#### 1. Модульные тесты (Unit)
*Что тестируют:* Изолированную бизнес-логику, мапперы, утилиты. Без поднятия контекста Spring.
* Запуск через терминал:
  ```bash
  ./gradlew test --tests "*Test"
  ```

#### 2. Интеграционные тесты (Integration / IT)
*Что тестируют:* Взаимодействие компонентов, контроллеры, репозитории. Используют реальную базу данных в Docker-контейнере через **Testcontainers**.
*Требования:* На машине должен быть запущен **Docker Desktop / OrbStack / Podman**.
* Запуск через терминал:
  ```bash
  ./gradlew test --tests "*IT"
  ```

#### 3. Архитектурные тесты (ArchUnit)
*Что тестируют:* Соответствие кодовой базы правилам архитектуры слоев и пакетов. Предотвращают появление циклических зависимостей и «спагетти-кода».
* Запуск через терминал:
  ```bash
  ./gradlew test --tests "ru.practicum.crm.architecture.*"
  ```
